# Implementation Plan

## Goal

Build the markdown editor as a reusable `MarkdownDocument` package consumed by `apps/markdown`.

The first full build should establish the package boundary, native document adapter, macOS app shell, read-only rendering, stable block IDs, file opening, basic persistence, and then active block editing with native document transactions.

## Fixed Decisions

- Package name: `@legend-apps/markdown-document`.
- Package location: `packages/markdown-document`.
- Native core: wrap `@legend-apps/markdown-parser`; do not merge parser code into the component package yet.
- First milestone: read-only document rendering.
- First public component API: `filename + adapter`.
- Native adapter location: exported from `@legend-apps/markdown-document`.
- Platform scope: macOS first.
- Internal package state: React state/hooks/refs first. Do not add an `@legendapp/state` dependency to `@legend-apps/markdown-document`.
- App state: use `@legendapp/state` persistence for app metadata such as recent files and preferences.
- Future user customization is a key product goal. V1 defaults must not hardcode app chrome or make markdown/app-shell styling difficult to replace later.
- Block IDs: opaque strings generated by native in milestone 1.
- Block fetching: initial render window, then hydrate all remaining blocks after first paint.
- JS block cache owner: `MarkdownDocument`.
- Layout: rely on `LegendList` layout change detection. Do not key rows by revision or remount rows to force measurement.
- Enriched editor: rely on the current `react-native-enriched-markdown` API first. Work around or upstream PR missing APIs only when a real blocker appears.
- Undo/redo: JS owns history.
- Native transaction APIs: add with active editing, not during read-only milestone.
- Autosave: owned by `MarkdownDocument`, controlled by a `savePolicy` prop.
- Save API: native document session exposes save methods through the adapter.
- Save As: defer.
- Error surface: callbacks from `MarkdownDocument`; app renders status/errors.
- Native menu/open-file plumbing should be validated before document UI work. If native menu wiring is incomplete, prioritize fixing it rather than shipping fallback buttons.
- File watching/external reload is deferred.
- Startup launch file detection should use `process.argv`; fall back to opening the file dialog if argv does not expose the path.
- File writes should be UTF-8, atomic, and preserve dominant line endings when practical.
- Validation target: `bun run typecheck` plus launching/running `apps/markdown` on macOS and rendering a real markdown file.
- Automated tests: add only for pure TS helper logic if the implementation creates meaningful patch/history helpers.
- Commits should be split by milestone and every commit should leave the app/build in a working state.
- Stop and ask only for real blockers: architecture conflicts, native API impossibility, or risky data-loss behavior.

## Package Shape

Create:

```txt
packages/markdown-document/
  package.json
  src/
    index.ts
    MarkdownDocument.tsx
    adapters/
      nativeMarkdownDocumentAdapter.ts
    types.ts
    state/
    history/
    styles.ts
```

The package should depend on:

- `@legend-apps/markdown-parser`
- `@legendapp/list`
- `react-native-enriched-markdown`
- React / React Native peer dependencies following local package conventions

The package should not depend on:

- `@legendapp/state`
- app-specific file dialog/menu packages
- app-specific persistence

Public exports should include:

- `MarkdownDocument`
- native adapter
- command/types
- shared public types
- `defaultMarkdownStyle`

Keep history/cache internals private until they stabilize.

Add a short README with basic usage and API notes.

## Component API

Initial shape:

```tsx
<MarkdownDocument
  filename={filename}
  adapter={nativeMarkdownDocumentAdapter}
  savePolicy={savePolicy}
  style={style}
  contentContainerStyle={contentContainerStyle}
  markdownStyle={markdownStyle}
  theme={theme}
  onLoaded={handleLoaded}
  onDirtyChange={handleDirtyChange}
  onSaveStateChange={handleSaveStateChange}
  onError={handleError}
/>
```

`savePolicy` should be an object rather than several flat props:

```ts
type MarkdownSavePolicy = {
  autosave?: boolean;
  debounceMs?: number;
};
```

Default autosave policy:

- autosave enabled
- debounce no more than 2000ms
- explicit save flushes pending active-editor changes before writing
- save failures keep the document dirty
- save/autosave failures pause autosave retries until the next edit or explicit Save

Expose commands by ref or hook:

```ts
type MarkdownDocumentCommands = {
  save(): void;
  undo(): void;
  redo(): void;
  focus(): void;
  toggleBold(): void;
  toggleItalic(): void;
  insertLink(): void;
};
```

Menus and shortcuts in the app should call these commands instead of reaching into internal document state.

The component should expose command/state APIs that can drive future custom toolbars and formatting bars. Do not hardcode toolbar placement, button contents, or app-shell chrome inside `MarkdownDocument`.

## Adapter API

Initial adapter shape:

```ts
type MarkdownDocumentAdapter = {
  load(filename: string): Promise<MarkdownDocumentSnapshot>;
  getBlock(documentId: string, blockId: string): Promise<MarkdownBlockSnapshot>;
  getBlocks(
    documentId: string,
    startIndex: number,
    count: number,
  ): Promise<MarkdownBlockSnapshot[]>;
  save(documentId: string): Promise<void>;
  close(documentId: string): Promise<void>;
};
```

Editing phase adds:

```ts
applyTransaction(
  documentId: string,
  transaction: MarkdownTransaction,
): Promise<MarkdownTransactionResult>;
```

The native adapter should wrap `@legend-apps/markdown-parser` and hide parser-specific object details from the React component.

## Parser Package Changes

Milestone 1 should extend `@legend-apps/markdown-parser` enough for stable read-only rendering:

- native document session ID
- opaque block IDs
- source byte ranges
- content byte ranges if available
- block render metadata
- initial block window
- lazy block range fetch

Read-only block snapshot:

```ts
type MarkdownBlockSnapshot = {
  id: string;
  index: number;
  type: string;
  depth: number;
  markdown: string;
  sourceStartByte: number;
  sourceEndByte: number;
  contentStartByte?: number;
  contentEndByte?: number;
  textRevision: number;
};
```

IDs should be opaque strings such as `d1:b42`. JS must not parse them.

Native source/editing details:

- Store the edited source as a simple native string/buffer first.
- Expose UTF-8 byte ranges in snapshots.
- JS editor APIs continue to use block-local UTF-16 offsets.
- If `updateBlockMarkdown` unexpectedly changes markdown structure, use dirty-region parsing first.
- Nitro spec changes should include generated files in the same implementation pass.
- Keep the existing kitchen-sink markdown-parser example working when parser APIs change.
- Native parser tests are not required initially unless an obvious low-cost test path already exists.

File format details:

- UTF-8 only.
- Invalid encoding is a load error.
- Preserve dominant line endings on save when practical.
- Save with an atomic replace strategy.

## App Shell

`apps/markdown` should consume `@legend-apps/markdown-document`.

Startup behavior:

- If launched with a `.md` file argument, open that file.
- If multiple `.md` file arguments are present, open the first one.
- If no markdown file argument is present, open the file dialog immediately.
- File -> Open opens the file dialog.
- If startup file loading fails, show the error and open the file dialog.
- If the startup file dialog is canceled, keep the app process open with no document window. This is best effort if the shell needs support work.
- V1 remains single-window. New-window behavior is deferred.
- If opening a different file while the current document is dirty, prompt Save / Discard / Cancel before replacing the document.
- If Save during that prompt fails, show the error and stay on the current document.
- If a dirty window closes, prompt Save / Discard / Cancel.
- If Save during close fails, show the error and keep the window open.
- Do not watch the open file for external changes in v1.

V1 menu scope:

- Open
- Save
- Undo
- Redo
- Bold
- Italic
- Link

Recent files:

- Implement basic recent files in the first build pass.
- Persist recent files with `@legendapp/state`.
- Persist with JSON-backed app metadata.
- Persist file path, display title, and last opened timestamp.
- Keep up to 20 recent files.
- If a recent file is missing, show an error and remove it from recents.
- Show recent files in the native menu if dynamic menu support is straightforward.
- Do not build an empty-state recent-files list.

App-level state should include:

- current filename
- recent files
- load/save status
- last error
- basic preferences when needed

## Read-Only Milestone

1. Validate/fix native menu command plumbing.
2. Create `packages/markdown-document`.
3. Export types, adapter, helpers, and `MarkdownDocument`.
4. Extend `@legend-apps/markdown-parser` with stable block IDs and richer block snapshots.
5. Render a loaded file with `LegendList`.
6. Use block IDs as list data and keys.
7. Fetch 64 blocks for first paint.
8. Hydrate all remaining blocks after `LegendList` load/first paint in chunks of 512.
9. Build package defaults that feel like a native document app: readable centered content column, sensible padding, and overridable styles.
10. Wire `apps/markdown` to open a markdown file and render it.
11. Add recent files persistence.
12. Keep DEV-only parse timing/block count diagnostics available, but do not show them in normal UI.

## Editing Milestone

After read-only rendering is stable:

1. Click/tap a block to activate editing.
2. Swap that block to `EnrichedMarkdownTextInput`.
3. Use current enriched APIs:
   - `onChangeMarkdown`
   - `onChangeSelection`
   - `onChangeState`
   - focus/blur
   - inline formatting commands
   - link commands
   - `getMarkdown`
   - caret rect APIs
4. Commit active block edits with debounced `onChangeMarkdown`.
5. Use a 300ms debounce for document commits.
6. Mark the document dirty immediately on editor changes, before the debounced transaction completes.
7. Immediately flush pending active-editor changes when switching blocks, blurring, pressing Escape, or saving.
8. Blur returns the block to rendered mode.
9. Escape commits and blurs.
10. Best effort: place the cursor near the click position when activating a block. Fall back to focusing at the end.
11. Use the enriched component for all active block editing. Do not build separate fallback editor logic for unsupported markdown types.
12. Keep an empty active block as an empty paragraph until structural delete/merge removes it.
13. Add native `applyTransaction` with `updateBlockMarkdown`.
14. Preserve the block ID for block-local edits.
15. Return range patches from native to JS.
16. Update `blockIds` and `blocksById` in `MarkdownDocument`.
17. Schedule autosave according to `savePolicy`.

Enter/split behavior:

- Enter should split the current block in v1.
- If direct Enter interception is missing from enriched input, use the markdown change callback and newline detection as a temporary workaround.
- Left/original block keeps the original ID.
- New/right block gets a new ID and becomes active.
- List continuation is best effort; improve later if needed.

Backspace and paste:

- Backspace-at-start uses enriched input default behavior first.
- Paste uses enriched input default behavior first.
- Add merge/paste structural handling only when a concrete blocker appears.

Initial transaction types:

```ts
type MarkdownTransaction =
  | { type: "updateBlockMarkdown"; blockId: string; markdown: string }
  | { type: "splitBlock"; blockId: string; offsetUtf16: number }
  | { type: "mergeWithPrevious"; blockId: string }
  | { type: "replaceBlocks"; blockIds: string[]; markdown: string };
```

Initial transaction result:

```ts
type MarkdownTransactionResult = {
  revision: number;
  sourceLength: number;
  changedRange: {
    startBlockIndex: number;
    deleteCount: number;
    blockIds: string[];
  };
  changedBlocks: MarkdownBlockSnapshot[];
  retiredBlockIds: string[];
};
```

## Undo/Redo

JS owns undo/redo.

Typing should be grouped:

- coalesce continuous typing in the same block
- split groups after a 1000ms pause
- split groups on blur
- split groups on selection jump
- split groups on formatting command
- split groups on structural command

Undo entries should store:

- forward transaction
- inverse transaction or inverse patch
- selection restore data
- retired/restored block ID metadata when needed

Save and dirty-state interactions:

- Undo history survives manual saves and autosaves.
- Track the saved document revision.
- Dirty becomes false when the current revision equals the last saved revision.
- Save while typing flushes the active editor, applies pending transactions, then writes.

Block clipboard and whole-block multiselect UI are deferred. Use native/enriched text clipboard behavior inside the active editor first.

No visible formatting toolbar in v1. Wire command/menu/shortcut behavior first.

## Layout And Measurement

Rely on `LegendList` layout change detection.

Do not:

- remount rows by changing React keys for normal edits
- key rows by content revision
- reset the whole list for normal block-local edits

If enriched markdown async rendering changes height without a list-visible layout event, treat it as an enriched markdown/native layout invalidation issue. Work around or PR the library only when confirmed by runtime behavior.

## Styling

Initial visual direction:

- Native document app feel, not the kitchen-sink benchmark UI.
- Readable centered content column by default.
- Package provides default padding.
- App/package styles remain overridable through props.
- Export `defaultMarkdownStyle`.

Future customization requirement:

- All markdown styles must be externally configurable.
- Document width, position, alignment, and padding must be configurable.
- Defaults are replaceable; they are not behavior.
- App shell chrome belongs to the app, not `MarkdownDocument`.
- Top toolbars, bottom toolbars, formatting bars, button placement, and button sizing should be slots/configuration in the app shell later.
- `MarkdownDocument` should expose enough command/state APIs for custom app chrome to control formatting, save, undo, redo, and selection-sensitive UI.

V1 should avoid:

- built-in document header chrome inside `MarkdownDocument`
- fixed toolbar assumptions
- fixed button layouts
- styling logic that assumes a single document width forever
- internal-only markdown style constants that cannot be replaced

## Validation

Before calling the implementation pass complete:

1. Run `bun run typecheck`.
2. Run `bun run markdown run macos`.
3. Verify the app opens a markdown file from startup/file dialog.
4. Verify a large markdown file renders without scroll gaps after hydration.
5. Verify File -> Open, Save, Undo, and Redo are wired when their implementation phase is complete.
6. Verify every milestone commit leaves the build working.
7. Add focused tests only if pure TS patch/history helpers are introduced.

Performance target:

- Validate with 10k-20k block markdown documents.
- No explicit max file size in v1; attempt to load selected UTF-8 markdown files and surface load errors.
